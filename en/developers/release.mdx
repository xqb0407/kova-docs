## One-command packaging (macOS)

```bash
./scripts/build-release.sh
```

It runs: environment preflight → sidecar build → renderer build → main-process build →
installer.

<CodeGroup>
```bash Common flags
--skip-install    skip bun install when dependencies are already current
--check           environment preflight only, no build
--dev-channel     build Kova Dev.app (dev channel); default is the production channel
```
</CodeGroup>

Artifacts land in `apps/electron/release/` (`release-dev/` for the dev channel) as
`.dmg` / `.app`. The macOS bundle is **ad-hoc deep-signed** during packaging
(`apps/electron/scripts/after-pack.cjs`) and not notarized — first launch needs one GUI
confirmation.

## Windows packaging

Windows goes through `electron-builder --win nsis`, the same chain as CI:

```bash
bun run package:win        # artifact: release/Kova_<version>_<arch>-setup.exe
bun run package:win:dev    # artifact: release-dev/… (dev channel)
```

It only runs on Windows; stop `bun dev` / `next dev` first so the watcher does not restart
Electron during the build.

## Step-by-step builds

The three chains can run separately; together they equal `bun run build`:

<CodeGroup>
```bash Terminal
bun run build:sidecar    # sidecar → apps/electron/binaries/kova-worker
bun run build:renderer   # renderer static export → renderer-out
bun run build:main       # main process / preload → apps/electron/dist

bun run build            # all three chains
bun run start            # run the built main process (no hot reload, like an installed build)
```
</CodeGroup>

## Packaging ≠ releasing

These two get conflated, but they are different jobs:

| | What it does | Who does it |
| --- | --- | --- |
| **Package** | Compile an installer | `build-release.sh` / `bun run package:win` |
| **Release** | Sync versions, tag, push | `node scripts/release.mjs <version>` |
| **Mirror to GitHub** | Push the mirror and clean tags/history | `./scripts/sync-github.sh` |

Pushing a tag triggers CI (`.github/workflows/release.yml`): it first creates a Draft
Release, then the macOS (`macos-14`, producing the dmg + `SHA256SUMS-macos.txt`) and
Windows (NSIS setup.exe) jobs package and `gh release upload` straight into that draft.
Before publishing, check the dmg / exe and the SHA256SUMS. `release.mjs` **only** syncs
versions, tags, and pushes.

## Versions

Versions come from a single source, synced across `package.json`, `apps/electron`, and the
workspace packages. `release.mjs` syncs versions before tagging. Do not hand-edit a single
`package.json`.

## Release checklist

<Steps>
  <Step title="Preflight">
    `./scripts/build-release.sh --check`.
  </Step>
  <Step title="Confirm the gate passes">
    ```bash
    bun run verify:goal        # full gate
    ```
  </Step>
  <Step title="Package and verify the installer">
    Take the installer from the artifact directory, install it once in a clean environment,
    and smoke it — especially key reads/writes and sidecar startup. End-to-end smoke
    scripts live in `apps/electron/scripts/`.
  </Step>
  <Step title="Release">
    Check with `node scripts/release.mjs <version> --dry-run`, then drop `--dry-run`;
    pushing the tag makes CI produce the Draft Release. Use `./scripts/sync-github.sh`
    afterwards if you need the GitHub mirror.
  </Step>
</Steps>
