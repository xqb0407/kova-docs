## In progress: mobile app

The native shell has shipped (Expo, reusing the desktop gateway's `/ws` protocol — same
origin as the browser web client). What remains is what mobile scenarios actually need:

- **Push notifications**: task done, waiting for approval, automation results;
- **Biometric unlock + token rotation**: tokens are long-lived today, revocation only via
  "Revoke all devices" on the desktop;
- **Offline drafts and weak-network experience**: queued sends and in-flight stream resume
  across cellular / Wi-Fi switches;
- **Narrow-screen polish**: gestures, attachment picking, session list layout.

## In progress: remote capability

From "works on the same Wi-Fi" to "safe to use away from home":

- **End-to-end encryption**: key agreement after pairing, WS traffic encrypted at the
  desktop, zero plaintext at the cloud (tunnel / relay);
- **Stable public entry**: move beyond temporary tunnel addresses; fixed domains and
  automatic reconnect;
- **Multi-device concurrency**: input arbitration and view sync with desktop + several
  remotes online;
- **Remote approvals**: push dangerous-operation confirmations to paired devices and
  approve them there.
