## Requirements

Running from source needs three things:

| Dependency | Version | Purpose |
| --- | --- | --- |
| [Bun](https://bun.sh) | ≥ 1.x | Dependency installation and workspace scripts |
| Node.js | ≥ 20 | Build scripts and Electron runtime dependencies |
| OS | macOS / Windows | The desktop shell currently ships for these two platforms |

## Install and run the desktop app

<Steps>
  <Step title="Clone and install dependencies">
    ```bash
    git clone https://github.com/xqb0407/kova.git
    cd kova
    bun install
    ```

    This is a workspace repo: `bun install` sets up `apps/*`, `apps/sidecar/*`, and
    `packages/*`. If the Electron binary is missing (common on restricted networks),
    run `node apps/electron/node_modules/electron/install.js` once.
  </Step>
  <Step title="Start development mode">
    ```bash
    bun run dev
    ```

    One command brings up all three layers with hot reload: `next dev` for the
    renderer (:3000, HMR), an esbuild `--watch` build of the main process (Electron
    restarts itself when `dist/*.cjs` changes), and the agent sidecar. No Rust, no
    long compile wait.
  </Step>
  <Step title="Configure a model">
    Open Settings → Models and add an API key for a provider. Credentials are encrypted
    with AES-256-GCM into the local database, with the master key wrapped by the system
    keychain (safeStorage) — never stored in plaintext. See
    [Security & keys](/en/features/security).
  </Step>
</Steps>

## Common commands

<CodeGroup>
```bash Terminal
# Desktop development (renderer + main + sidecar, each hot-reloading)
bun run dev

# Production builds (three chains, runnable separately)
bun run build:sidecar    # sidecar → apps/electron/binaries/kova-worker
bun run build:renderer   # renderer static export → renderer-out
bun run build:main       # main process / preload → apps/electron/dist
bun run build && bun run start   # full build and run (no hot reload, like an installed build)

# Tests and gates
bun run test             # sidecar unit tests
bun run test:desktop     # desktop unit tests
bun run test:protocol    # protocol unit tests
bun run verify:goal      # full gate (goal/desktop/protocol/runtime tests + typecheck of three packages)

# Mobile (start the desktop remote gateway and allow LAN access first)
bun run dev:mobile
bun run typecheck:mobile
bun run test:mobile
bun run build:mobile:web   # web static export → apps/mobile/dist
```
</CodeGroup>

## Smoke the sidecar without the UI

The sidecar is a standalone process and can be started on its own for a protocol smoke:

```bash
cd apps/sidecar/pi-agent && bun run smoke
```

It starts with the NDJSON protocol on stdin/stdout — useful for checking the protocol
handshake, tool registration, and session reads/writes. Fuller end-to-end smoke
(renderer bridge marker, chat, git, remote gateway) lives under
`apps/electron/scripts/`, run against `--remote-debugging-port`; see the repo README.

## Dev vs production data isolation

This is easy to trip over, so it gets its own section.

Dev mode (unpackaged runs, or starting with `--dev`) uses the separate app identifier
`com.kova.assistant.dev`, shown as "Kova Dev". Its data directory therefore becomes:

```
~/Library/Application Support/com.kova.assistant.dev
```

Three consequences:

- Installing or uninstalling the production build **does not** touch dev data, and vice versa;
- The production (packaged) build uses `com.kova.assistant`; the two cannot read each other's ciphertext;
- For further isolation between multiple instances / e2e runs, override the data directory:
  `KOVA_DATA_DIR=/tmp/kova-sandbox`.

<Warning>
  The `~/.kova/` global layer is **intentionally shared** — it is the machine-level config
  layer (memory, subagent definitions, system MCP config, etc.) and not managed by the
  installer. Isolation only applies to the `Application Support` layer.
</Warning>

## FAQ

<AccordionGroup>
  <Accordion title="Rebranding the app">
    This is a template repo; rebranding is one command:
    ```bash
    ./scripts/rename.sh <new-slug> [--app-name "Display name"] [--bundle-id com.x.y] [--dry-run]
    ```
    The script covers the brand's three forms (slug / Pascal / UPPER), the
    `electron-builder.yml` productName / appId, the runtime identifier and window title
    in the main process `paths.ts`, and backs up files before changing them.
  </Accordion>
  <Accordion title="Port 3000 is taken / pointing at another renderer">
    Use `KOVA_DEV_URL` for the renderer address, `KOVA_DATA_DIR` for the data directory,
    and `bun run dev -- --remote-debugging-port=9222` to pass flags through to Electron.
  </Accordion>
</AccordionGroup>
