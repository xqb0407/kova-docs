## 环境要求

从源码运行需要三样东西：

| 依赖 | 版本 | 用途 |
| --- | --- | --- |
| [Bun](https://bun.sh) | ≥ 1.x | 依赖安装与工作区脚本 |
| Node.js | ≥ 20 | 构建脚本与 Electron 运行时依赖 |
| 操作系统 | macOS / Windows | 桌面壳目前打包这两个平台 |

## 安装并运行桌面端

<Steps>
  <Step title="克隆并安装依赖">
    ```bash
    git clone https://github.com/xqb0407/kova.git
    cd kova
    bun install
    ```

    这是一个 workspace 仓库，`bun install` 会同时装好
    `apps/*`、`apps/sidecar/*` 与 `packages/*`。
    如果 Electron 二进制缺失（常见于网络受限环境），补跑一次
    `node apps/electron/node_modules/electron/install.js`。
  </Step>
  <Step title="起桌面端开发模式">
    ```bash
    bun run dev
    ```

    这一条命令会同时拉起三层，各自热更新：渲染层 `next dev`（:3000，HMR）、
    主进程 esbuild --watch（`dist/*.cjs` 变更后自动重启 Electron）、
    以及 agent sidecar 进程。没有 Rust、不用等编译。
  </Step>
  <Step title="配置模型">
    在应用内打开设置 → 模型，添加一个供应商的 API Key。
    凭据以 AES-256-GCM 加密落在本机数据库，主密钥由系统钥匙串（safeStorage）包裹，
    不会明文落盘。详见[安全与密钥](/features/security)。
  </Step>
</Steps>

## 常用命令

<CodeGroup>
```bash Terminal
# 桌面端开发（渲染层 + 主进程 + sidecar，各自热更）
bun run dev

# 生产构建（三条链，可分别执行）
bun run build:sidecar    # sidecar → apps/electron/binaries/kova-worker
bun run build:renderer   # 前端静态导出 → renderer-out
bun run build:main       # 主进程 / preload → apps/electron/dist
bun run build && bun run start   # 全量构建并运行（无热更，等价装机版）

# 测试与门禁
bun run test             # sidecar 单测
bun run test:desktop     # 桌面端单测
bun run test:protocol    # 协议单测
bun run verify:goal      # 全量门禁（goal/桌面/协议/运行时测试 + 三包 typecheck）

# 移动端（需桌面端先开远程网关并允许局域网访问）
bun run dev:mobile
bun run typecheck:mobile
bun run test:mobile
bun run build:mobile:web   # web 静态导出 → apps/mobile/dist
```
</CodeGroup>

## 不开界面也能验 sidecar

sidecar 是独立进程，可以单独拉起来做协议冒烟：

```bash
cd apps/sidecar/pi-agent && bun run smoke
```

它会以 stdin/stdout 上的 NDJSON 协议独立启动，用来检查协议握手、工具注册和
会话读写是否正常。更完整的端到端冒烟（渲染层桥标记、聊天、git、远程网关）
在 `apps/electron/scripts/` 下，配合 `--remote-debugging-port` 跑，见仓库 README。

## dev 与正式版的数据隔离

这一点很容易踩坑，所以单独说明。

dev 模式（未打包运行，或带 `--dev` 启动）使用独立的应用标识
`com.kova.assistant.dev`，显示名「Kova Dev」。于是应用数据目录变成：

```
~/Library/Application Support/com.kova.assistant.dev
```

三个结论：

- 安装或卸载正式版**不会**动到 dev 的数据，反之亦然；
- 正式（打包版）走 `com.kova.assistant`，两者密文互不可读；
- 想在多实例 / e2e 之间进一步隔离，用环境变量覆盖数据目录：
  `KOVA_DATA_DIR=/tmp/kova-sandbox`。

<Warning>
  `~/.kova/` 全局层是**有意共用**的——它是机器级的配置层（记忆、子代理定义、
  MCP 系统层配置等），不归安装器管辖，所以隔离只发生在 `Application Support`
  这一层。
</Warning>

## 常见问题

<AccordionGroup>
  <Accordion title="想换成自己的品牌">
    这是模板仓库，改品牌一条命令：
    ```bash
    ./scripts/rename.sh <new-slug> [--app-name "显示名"] [--bundle-id com.x.y] [--dry-run]
    ```
    脚本覆盖品牌三形态（slug / Pascal / UPPER）、
    `electron-builder.yml` 的 productName / appId、主进程 `paths.ts` 里的运行期
    identifier 与窗口标题等，改动前会自动备份。
  </Accordion>
  <Accordion title="端口 3000 被占 / 想连另一个渲染层">
    用 `KOVA_DEV_URL` 指定渲染层地址，`KOVA_DATA_DIR` 换数据目录，
    `bun run dev -- --remote-debugging-port=9222` 透传参数给 Electron。
  </Accordion>
</AccordionGroup>
