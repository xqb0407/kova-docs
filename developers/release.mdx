## 一键打包（macOS）

```bash
./scripts/build-release.sh
```

依次做：环境预检 → 构建 sidecar → 构建前端 → 构建主进程 → 产出安装包。

<CodeGroup>
```bash 常用参数
--skip-install    依赖已最新时跳过 bun install
--check           只做环境预检，不实际构建
--dev-channel     出 Kova Dev.app（dev 渠道），默认出正式渠道
```
</CodeGroup>

产物在 `apps/electron/release/`（dev 渠道为 `release-dev/`）下的 `.dmg` / `.app`。
macOS 包在打包流程里做 **ad-hoc 深签**（`apps/electron/scripts/after-pack.cjs`），
未公证 → 用户首次打开需一次 GUI 引导。

## Windows 打包

Windows 走 `electron-builder --win nsis`，一条与 CI 相同的链路：

```bash
bun run package:win        # 产物 release/Kova_<version>_<arch>-setup.exe
bun run package:win:dev    # 产物 release-dev/…（dev 渠道）
```

只在 Windows 上运行；打包前先停掉 `bun dev` / `next dev`，避免 watcher
在构建期间重启 Electron。

## 分步构建

三条构建链可以分别执行，合起来等价于 `bun run build`：

<CodeGroup>
```bash Terminal
bun run build:sidecar    # sidecar → apps/electron/binaries/kova-worker
bun run build:renderer   # 前端静态导出 → renderer-out
bun run build:main       # 主进程 / preload → apps/electron/dist

bun run build            # 三条链全量
bun run start            # 跑已构建的主进程（无热更，等价装机版）
```
</CodeGroup>

## 打包 ≠ 发版

这两件事经常被混在一起，但职责完全不同：

| | 做什么 | 谁做 |
| --- | --- | --- |
| **打包** | 编译出安装包 | `build-release.sh` / `bun run package:win` |
| **发版** | 版本号同步、打 tag、推送远端 | `node scripts/release.mjs <版本号>` |
| **镜像到 GitHub** | 推送镜像并清理 tag 与历史 | `./scripts/sync-github.sh` |

推 tag 会触发 CI（`.github/workflows/release.yml`）：先建好 Draft Release，
再由 macOS（`macos-14`，出 dmg + `SHA256SUMS-macos.txt`）与 Windows（NSIS setup.exe）
两个 job 打包，直接 `gh release upload` 传进该 draft。发布前请核对 dmg / exe
与 SHA256SUMS。`release.mjs` **只**做版本号同步、打 tag 与推送远端。

## 版本号

版本号是单一来源的，跨 `package.json`、`apps/electron` 与各 workspace 包同步。
`release.mjs` 会先做版本号同步再打 tag。改版本号时不要只手改某一个 `package.json`。

## 发布检查清单

<Steps>
  <Step title="环境预检">
    `./scripts/build-release.sh --check`。
  </Step>
  <Step title="确认门禁通过">
    ```bash
    bun run verify:goal        # 全量门禁
    ```
  </Step>
  <Step title="打包并验证安装包">
    从产物目录取安装包，在干净环境装一次再跑冒烟，
    尤其验证密钥读写与 sidecar 拉起。端到端冒烟脚本在 `apps/electron/scripts/`。
  </Step>
  <Step title="发版">
    `node scripts/release.mjs <版本号> --dry-run` 核对后去掉 `--dry-run`，
    推 tag 让 CI 出 Draft Release；需要 GitHub 镜像时再跑 `./scripts/sync-github.sh`。
  </Step>
</Steps>
