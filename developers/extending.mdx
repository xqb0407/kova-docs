## 写一个插件

插件是「一个目录 + 一份清单」，在插件仓库里开发，经市场安装进扣瓦。

<Steps>
  <Step title="建目录与清单">
    ```bash
    mkdir -p my-plugin/.kova-plugin
    ```

    清单是 `.kova-plugin/plugin.json`：
    ```json
    {
      "name": "my-plugin",
      "version": "0.1.0",
      "description": "一句话说明这个插件做什么",
      "author": { "name": "你" },
      "category": "效率",
      "icon": "icon.svg",
      "keywords": ["my", "plugin"],
      "skills": "skills",
      "panels": "panels.json",
      "mcpServers": ".mcp.json"
    }
    ```
  </Step>
  <Step title="决定要做哪几层">
    `skills/` 提供技能（agent 知道怎么做），
    `panels.json` 注册面板（人能打开来用），
    `.mcp.json` 贡献 MCP 服务器（agent 能调用）。
    另有 `hooks.json`（生命周期钩子）与 `subagents/`（预置子代理）。
    各层可以只做一层，也可以全做。
  </Step>
  <Step title="装进市场并调试">
    在市场根放一份 `marketplace.json` 列出你的插件，应用内「插件 → 添加市场」
    以**目录市场 + 链接安装**加进来——缓存目录指向源码，改文件即时生效
    （重新开会话或刷新市场即可）。
  </Step>
</Steps>

清单校验的硬错误（装不上）与软诊断（组件静默为空）见 `docs/plugin-development.md`，
里面还有技能、MCP、面板、hooks、子代理五类组件的完整字段说明与排障表。

## 接一个 MCP 服务器

要点：

- **多服务器连接池**：多个 MCP 服务器并发连接，互不阻塞；
- **配置三层合并**：系统层 `~/.kova/mcp.json`、工作区标准层 `.mcp.json`、
  工作区覆盖层 `.kova/mcp.json`，后者覆盖前者；
- **工具走 `mcp` 网关**：MCP 工具不直接进模型工具表（保护提示词前缀缓存），
  统一以全名 `<server>__<tool>` 经 `mcp` 网关调用；
- **输出防护与审批**：MCP 返回内容视为不可信输入，调用走同一套审批流程并留审计记录；
- **密钥注入**：stdio 服务器的环境变量可绑定到全局密钥，明文不落配置文件，
  详见[安全与密钥](/features/security)。

插件也可以通过清单里的 `mcpServers` 字段自带 MCP 服务器定义——
`ui-design` 就是这么做的，agent 因此能直接操作设计画布。

## 加一个技能

技能放在插件的 `skills/` 目录，或由用户级配置提供。
技能是装进 agent 上下文的知识包，在设置 → 技能里装载与管理。

一份技能就是一个 `SKILL.md`：`name` 与 `description` 必填，
`description` 决定**什么时候触发**（写触发场景而不是功能清单）。
内置的 iOS / Material / 通用移动端设计规范就是以技能形式分发的，
可通过 `use_skill` 按需加载，而不是一次性全塞进上下文。

## 加一个内置工具

工具实现在 `apps/sidecar/pi-agent/src/tools/`，在 `tools.ts` 里注册。
新增工具时必须同时决定它的权限行为：

<Warning>
  工具的"能不能用"由**会话模式**决定，"要不要问"由**权限档位**决定。
  两者在 UI 上是分开的两个下拉。新增工具时要同时挂到正确的维度上，
  否则会出现"在 plan 模式里居然能写文件"这类不一致。
</Warning>

## NDJSON 协议与跨端契约

<Columns cols={2}>
  <Column title="pi-protocol">
    `packages/pi-protocol` 定义跨端共享的契约。
    桌面前端、sidecar、移动端都从这里取类型。
    改协议时改这里，不要在任何一端另写一份。
  </Column>
  <Column title="NDJSON over stdio">
    主进程与 sidecar 之间的进程协议：一行一个 JSON 对象。
    业务表的读写与密钥解密走 host 桥，
    所以日志与协议在通道上有明确区分。
  </Column>
</Columns>

同一个 sidecar 实例同时服务桌面直连与远程 `/ws` 连接，
所以任何改动都要考虑"多端同时在线"下的行为。

## 一键换品牌

这是模板仓库，换成自己的品牌：

```bash
./scripts/rename.sh <new-slug> [--app-name "显示名"] [--bundle-id com.x.y] [--dry-run]
```

覆盖品牌三形态（slug / Pascal / UPPER）、`electron-builder.yml` 的
productName / appId、主进程 `main/paths.ts` 里的运行期 identifier 与窗口标题等，
改动前自动备份。

<Note>
  改名后确认 dev 与正式版的 identifier 区分（`com.kova.assistant.dev` /
  `com.kova.assistant`）仍符合预期——两者数据目录因此隔离，靠脚本改容易漏。
</Note>
