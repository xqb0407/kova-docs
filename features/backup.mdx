跑在本机的应用更需要备份。备份把你的全部数据打成 **`.piabk`** 包
（tar.gz + AES-256-GCM，支持口令加密），推到远程目标；
恢复走「staging + 重启换入」，校验通过才生效。

## 备份范围

**始终备份**（核心资产）：

- `state.db` —— 设置、会话索引、凭据密文、用量统计；
- `sessions/*.jsonl` —— 全部会话转录。

**按开关选择**：

- task-workspace、资料库、个人配置（`~/.kova/` 身份/记忆/MCP/审批 +
  桌宠/站点权限/设计主题）；
- 技能与插件；
- 检查点。

## 备份目标

| 目标 | 说明 |
| --- | --- |
| **S3 兼容对象存储** | PUT/GET/DELETE/ListObjectsV2，path-style；Secret Key 保存即清空、界面不回显 |
| **WebDAV** | 逐级建目录、PROPFIND 探测、幂等删除 |

备份过程逐阶段上报进度（打包 → 加密 → 上传），
每份包带 payload SHA256，恢复前逐文件校验。

## 恢复：staging + 重启换入

恢复不做原地热替换——那样一半成功一半失败最危险：

1. 选 `.piabk` 包（或从远程目标拉取）→ 解包到 staging 目录；
2. 逐文件校验哈希，JSONL 残行自动修剪；
3. 校验通过 → 打上「待恢复」标记 → **重启应用时原子换入**；
4. 只换入包里实际存在的分区——老包恢复到新版本不会删掉新增的数据。

<Warning>
  OS 钥匙串里的主密钥**不随备份走**（它属于那台机器）。换机恢复后需要
  重新输入 API Key；解不开的密文凭据会被自动清理，明文配置（自定义
  provider 等）原样保留。
</Warning>

## 数据库一致性

打包前先做 WAL checkpoint + `VACUUM INTO` 快照——备份的是一致状态，
不是写了一半的数据库文件。
