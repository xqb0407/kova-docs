访问加速让 WebFetch 与 git 在网络受限时也能顺畅访问 GitHub。
**默认为空 = 直连官方源**——默认流量不经任何第三方加速站，
加速是你的显式选择（设置 → 系统 → 访问加速）。

## 改写规则

| 主机 | 改写范围 |
| --- | --- |
| `raw.githubusercontent.com` 等文件主机 | 整站改写（加速收益最大、无副作用） |
| `github.com` | **只改下载类路径**（`/releases/download/`、`/archive/`、`/raw/`）——仓库页面国内多数网络能开，绕第三方反而更慢 |

镜像形态是 ghproxy 系：`加速前缀 + 原 URL`。换一家只需改设置，不必改代码。

## 凭据保护（硬边界）

- 带凭据的 URL **不改写**：私有仓库 raw 链接（`?token=…`）、
  用户名密码形式、凭据类 query 参数都原样直连；
- 带 `Authorization` / `Cookie` 头的请求不改写；
- **git push 一律不走镜像**——写操作的凭据既过不去、也不该发给第三方；
  SSH 远程形式天然不受影响。

## 怎么开启

- **设置 → 系统 → 访问加速**：选 ghproxy 系镜像站，或添加自定义
  `from → to` 规则（自定义规则优先于内建规则）；
- 分发方可启动前设 `PI_GITHUB_MIRROR` 给默认前缀（非法/空值 = 不改写）；
- 总开关关闭时整条改写路径跳过。

<Note>
  镜像站是第三方公共服务：可用性与返回内容由其运营方负责。
  自定义规则也是把流量送往你填写的地址——请自行评估后使用。
</Note>
