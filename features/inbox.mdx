---
title: "统一收件箱"
description: "把「需要你处理」和「刚完成、等你查看」的异步结果，从各个会话收拢成一个跨会话、跨端、可执行、可持久化的收件箱。"
---

后台 Agent 干活时，最怕的不是它出错，而是**你不知道它需要你**：
审批卡在某个没打开的会话里、子代理的报告没人看、自动化失败埋在运行历史里。
统一收件箱把这一切收拢到侧栏的一个入口。

## 收什么（v1 六类）

<Columns cols={2}>
  <Card title="审批（P0）">
    逐工具审批、MCP 网关审批、plan_exit 确认。
    动作：批准 / 拒绝 / 允许并记住 / 打开会话。
  </Card>
  <Card title="提问（P0）">
    `Question` 工具挂起的提问。
    动作：作答 / 取消 / 打开会话。
  </Card>
  <Card title="目标（P0/P1）">
    目标暂停、受阻、等待确认验收标准。
    动作：恢复 / 确认或调整标准。
  </Card>
  <Card title="自动化（P1/P2）">
    一次运行的成功或失败。
    动作：打开运行会话 / 重跑 / 归档。
  </Card>
  <Card title="子代理（P1/P2）">
    子代理进入终态（完成 / 失败 / 截断 / 停止 / 中断）。
    动作：打开父会话 / 打开报告 / 归档。
  </Card>
  <Card title="后台任务（P1/P2）">
    后台 bash 任务退出（非零退出 = 需要看）。
    动作：打开会话 / 归档。
  </Card>
</Columns>

刻意**不收**：每一轮正常结束、自动化 running/queued、子代理运行中的中间活动、
普通工具调用——收进来只会淹没真正需要你的事。

## 设计原则

<Columns cols={2}>
  <Card title="可执行优先">
    审批批准仍走 `tool_confirm`，回答仍走 `question_answer`，
    目标恢复仍走 `goal_resume`——收件箱不是新的权限通道，
    **不允许「直接放行」**，权限与审批边界全部照旧。
  </Card>
  <Card title="源权威">
    条目状态永远从事实源推导：审批的事实源是会话转录，
    自动化是任务运行历史，子代理是活动文件。源说已结算，收件箱不会还挂着 pending。
  </Card>
  <Card title="跨端一致">
    桌面、网页远程、移动端看到同一份条目与同一份已读/归档状态
    （`inbox_changed` 帧进远程广播白名单）。
  </Card>
  <Card title="可持久化 + 安静">
    重启、刷新、换端不丢；源已消失的条目显示「已失效」而不是报错。
    同一件事只产生一条，结算后不重复。
  </Card>
</Columns>

<Note>
  ACP 模式（编辑器里被拉起时）不启用收件箱——编辑器有自己的权限 UI，
  投影在该模式下 no-op，避免重复提醒。
</Note>

## 与未读徽标的关系

侧栏徽标从 localStorage 未读升级为收件箱的持久状态：
「需要你处理」的条目（P0/P1 失败）计入强提醒，「刚完成」的条目（P2 成功）
计入弱提醒。离开电脑一小时，回来先看收件箱，不用逐个会话翻。
