「项目」不只是一个工作目录——它可以是**一个主目录 + 若干附加代码工程
根目录**。前后端两个仓库、共享库、脚手架合并到同一张项目卡下，
项目内的所有对话共享同一套附加上下文（指令、技能、文件检索、写权限）。

## 术语

| 术语 | 含义 |
| --- | --- |
| 主目录 | 项目的身份目录，通常是会话 cwd，也是侧栏项目卡的 key |
| 附加根 | 主目录之外、合并进同一项目的代码工程目录 |
| 项目归属 | 会话实际挂在哪个主目录下——附加根里的会话也回主目录 |
| 生效目录 | 当前会话真正拿到的附加根列表（会排除 cwd 自身） |

## 合并规则

- cwd 等于主目录 → 拿到全部附加根；
- cwd 等于某个附加根 → 拿到主目录 + 其余附加根；
- **精确路径匹配**：开在附加根子目录里的会话不会自动并入——
  需要合并就把那个子目录本身添加为根；
- 未配置的目录可以被吸收：把 `backend` 加为 `frontend` 的根后，
  原本在 `backend` 里的会话自动归到 `frontend` 项目卡下。

## 附加上下文

每个附加根会注入：

- 指令文件（按 `AGENTS.md` → `CLAUDE.md` → `.claude/CLAUDE.md` 取第一个非空）；
- 技能目录（`.kova/skills`、`.agents/skills`、`.claude/skills`）；
- 文件检索范围与写权限根。

## 存储与安全

配置存本机 SQLite kv（`pi.projectDirs`），**刻意不放在仓库内**——
配置会注入指令与检索路径，如果跟随 git 走，clone 别人的仓库就能给
你的 Agent 注入指令，这是不可接受的默认值。代价是团队成员不自动共享
同一套虚拟目录（共享需要带信任确认的机制）。

管理入口：侧栏项目卡的「⋯」弹层 → 目录管理。
