自动化原本只有「到点跑」。**事件触发**把它扩展成：
Webhook 请求、文件变更、git 提交、IM 消息都能驱动一次 automation 运行；
桌面关掉窗口后任务**继续跑**（托盘常驻）。

## 四种触发源

| 触发源 | 防护 |
| --- | --- |
| **Webhook POST** | HMAC 签名 + 时间窗 + 幂等 + 限流 |
| **文件变更** | watcher 监听指定路径 |
| **git 提交** | HEAD 轮询 |
| **IM 消息** | IM 渠道旁路（钉钉/飞书/企微群里说句话就能触发） |

## 架构上最重要的一条

**触发器只是"另一种到点的方式"**。执行仍然走同一个
`PersistentTaskScheduler`（独立调度进程）——并发闸、运行历史、
错过补跑、单实例锁，全部免费获得。触发器不另起执行通路，
也就没有第二套需要维护的语义。

## Headless（托盘常驻）

关掉主窗口 ≠ 退出：托盘常驻时调度器与触发器继续工作，
Webhook 到了照样触发。两个明确的边界：

- **不做登录自启动**——像 VS Code：你开它才运行，运行期间才常驻；
- **不做独立 daemon**——依赖 Electron main 存活（v2 再议独立进程）。

## 管理入口

触发器随任务管理：每个自动化任务可以挂多个触发器
（`webhook | file | git | im`），启用/停用即时生效。
