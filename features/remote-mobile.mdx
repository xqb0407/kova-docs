扣瓦的移动端不是"另写一套客户端"，而是**桌面端开一个网关，
手机和浏览器当视口**。对话、工具执行、文件都还在桌面那边，
所以手机断网时桌面照常干活，重连后能接上。

## 工作原理

网页端是桌面助手的**远程入口**：所有 AI 处理、会话存储、文件操作都发生在你自己的
桌面客户端里（pi-agent sidecar）。开启远程访问后，桌面端会在同一端口同时提供
网页（HTTP）与对话通道（WebSocket），**网页界面由应用自身提供**，无需另外部署。

```
浏览器 ──http──▶ 桌面端网关（默认 0.0.0.0:8787）─┬─ 静态网页
        ──ws /ws──▶                            └─ WS 对话通道 ──▶ pi-agent sidecar
```

## 首次配对

<Steps>
  <Step title="桌面端开启远程网关">
    设置 → 远程访问 → 开启网关。
  </Step>
  <Step title="扫码或输配对码">
    手机扫描设置页二维码，或访问显示的地址（如 `http://192.168.1.5:8787`），
    配对码已自动填入；也可手动输入 6 位配对码。
  </Step>
  <Step title="配对码换 token">
    配对成功换取长效 token，之后免输入。token 在桌面端 SQLite 中**加密落盘**，
    浏览器端存在 localStorage（键 `pi.remote`）。配对码只存在内存中，
    重启网关即失效；输错 5 次该连接被锁定，可在桌面端"换一个"。
  </Step>
</Steps>

桌面端与网页端可同时在线，共享同一份本地会话。

## 断线与恢复

- 断线后自动重连：3 秒起指数退避、30 秒封顶；移动端回到前台立即重试一次。
- 重连成功后以**桌面端快照**重新对齐：断线期间的转录、在飞回复、排队消息、
  待审批都会补齐。重连以快照为权威，不承诺逐帧回放。
- 断线期间发送的消息进入本地待发队列，重连后自动补发；网关按 `requestId` 去重，
  同一条消息不会重复执行。
- 若 token 已被桌面端撤销，只能重新配对。

## 四种网络接入

桌面网关只监听本机端口，需要一种方式让外部网络到达它：

<Columns cols={2}>
  <Column title="局域网直连（默认可用）">
    同一 Wi-Fi 下，手机扫码或直接访问设置页显示的地址。
    Windows 首次开启网关时系统会弹防火墙授权，需允许。
  </Column>
  <Column title="内置 Cloudflare 快速隧道（推荐）">
    设置 → 远程访问 → 「公网访问」一键开启：应用自动拉起 cloudflared
    （本机没有时可一键下载并校验），换到一个临时公网地址，
    免费且**不需要 Cloudflare 账号**。地址每次启动都会变化；
    停止网关会联动收掉隧道。
  </Column>
  <Column title="手动命名隧道（固定域名）">
    需要固定域名时自行创建命名隧道，把流量回源到 `http://localhost:8787`。
    见 `docs/remote-access.md` 里的 `cloudflared` 命令。
  </Column>
  <Column title="Tailscale（免暴露公网）">
    桌面与访问设备登录同一 Tailscale 账号，走 WireGuard 加密的私有网络地址。
  </Column>
</Columns>

其他任何 WebSocket 客户端也能接入——非浏览器客户端直连 `ws://<IP>:8787/ws`，
协议见 `apps/electron/main/remote.ts` 头部注释。

## 安全须知

<Warning>
  网页端具备你桌面端助手的对话与文件操作能力，请勿把地址、配对码、token
  泄露给不信任的人。

  - **管理面消息在网关一律拒绝**（仅限桌面端）：凭据/AI 服务、MCP、技能、子代理、
    记忆与个性化、模型属性、自动化等；远程只保留会话/聊天类操作。
    API Key 从协议层就不再回传网页端（只回掩码）。
  - token 长效不过期，撤销靠桌面端「撤销所有设备」或关闭网关。
  - 绑定模式可在设置页关闭「局域网访问」：网关改绑 `127.0.0.1`，仅本机可连
    （配隧道/Tailscale 时用）。
  - 快速隧道只在设置页显式开启后才建立；知道公网地址的人仍需配对码才能接入。
  - 局域网 HTTP 为明文，敏感环境建议走 Tailscale 或隧道（TLS 在边缘终结）。
</Warning>

## 远程网页端的功能边界

| 功能 | 可用性 |
| --- | --- |
| 流式聊天 / 中断 | ✅ |
| 会话列表 / 历史回放 / 重命名 / 删除 | ✅ |
| 模型与技能设置 | ❌（网关拒绝管理类消息，桌面端专属） |
| 凭据 / API Key | ❌（协议只回掩码） |
| 工作区目录选择 | ❌（远程新会话使用桌面端用户主目录） |
| 安装 / 卸载插件 | ❌（插件市场是桌面本地行为） |

中断（abort）是全局的：网页端中断会同时打断桌面端正在进行的回复，反之亦然。

## SSH 远程项目

除了"桌面执行 + 远程视口"，还有另一种远程形态：**本地 runtime + 远程执行器**。
agent 循环、模型调用、UI、会话都在本地；`bash`/`read`/`write`/`edit` 等工具调用
通过系统 `ssh` 打到远端机器执行。不部署 daemon，远端只要有 sshd 和代码即可。

- 会话带远程目标时，工具执行改走系统 `ssh` 命令（免装依赖，白送
  ProxyJump、`~/.ssh/config` 别名与 agent 认证），连接复用用 `ControlMaster`。
- **密钥不进 sidecar**：密钥/agent 认证由 ssh CLI 直读 `~/.ssh/`；
  密码认证走 ssh2，密码只在主进程解密注入，渲染层仅见"是否设了密码"标志。
- **审批门留在 sidecar**：远程命令照样过[权限档位](/features/modes)与审批策略；
  写入根收敛到远端项目目录，双侧校验。
- 远端会话诚实降级：跳过沙箱与逐文件检查点，隐藏本地文件树 / Git 面板 /
  本地目录选择器，远端 git 快照经 ssh 且失败时降级为"无 git 信息"。

SSH 主机在设置 → 连接 → SSH 主机里增删改与测试，会话里用「新建远程项目…」选择主机与源文件夹。

## 移动 App

<CardGroup cols={2}>
  <Card title="技术选型">
    Expo + React Native + `@assistant-ui/react-native`。复用桌面网关的 `/ws` 协议，
    与浏览器网页端同源，不另写一套客户端。
  </Card>
  <Card title="开发命令">
    桌面端先开远程网关并允许局域网访问，然后：
    `bun run dev:mobile` · `bun run typecheck:mobile` ·
    `bun run test:mobile` · `bun run build:mobile:web`。
  </Card>
</CardGroup>

移动端依赖装在 `apps/mobile/node_modules`（`install.hoistingLimits = "workspaces"`），
RN 只能配特定 react 版本，与桌面各持一份，避免 Metro 双实例。

## Agent 始终跑在桌面

这一点决定了远程访问在体验上意味着什么：模型调用、工具执行、文件读写全在桌面侧的
sidecar 里，手机连的是一个视口，不是一个被降级过的第二套实现。手机息屏、切后台、
掉 Wi-Fi，都不影响桌面上正在跑的任务；重新连上后看到的是同一个回合的延续。

<Note>
  当前形态下，审批卡会出现在你正在使用的那个客户端上。
  在桌面发起并在桌面批准是安全的；在手机上批准则要清楚自己批的是什么。
  这一层的安全性依赖于配对设备本身可信，而不是每次都重新鉴权。
</Note>

## 还没做的

移动端真正的短板在"离开电脑"这件事上，目前还没有：

- 推送通知（任务完成、等待审批、定时任务结果到手机）；
- 生物识别解锁与 token 轮换；
- 离线草稿与弱网下的排队发送、流中断续播；
- 窄屏交互打磨（手势、附件选择、会话列表重排）。

这些都在[路线图](/reference/roadmap)里。当前形态适合"手机当随身遥控器，
真正干活的还是桌面"，而不是反过来。
